# Задание 1. Разбор tsconfig.json

Откройте `tsconfig.json` в корне проекта и для каждой строки напишите
**своими словами**, что она делает. Не копируйте документацию —
объясните так, как будто рассказываете одногруппнику.

## compilerOptions
> Это главный блок настроек компилятора TypeScript (наш пульт управления). Все параметры внутри этого блока определяют, насколько строго нужно проверять код и по каким правилам превращать его в обычный JavaScript

### target
> Эта строчка указывает, в какую именно версию JavaScript компилятор должен превратить наш TypeScript-код. Это нужно, чтобы готовый код без проблем запускался в старых браузерах или старых версиях Node.js

### module
> Задаёт систему модулей для готового JavaScript-кода (например, CommonJS или ESNext). Простыми словами — определяет, каким именно синтаксисом файлы будут импортировать код друг из друга (через ключевые слова `require` или `import`)

### moduleResolution
> Это алгоритм, по которому TypeScript ищет файлы на компьютере, когда мы пишем `import ...`. Он подсказывает компилятору, нужно ли искать модули только в папке `node_modules` (как это делает Node.js) или использовать другие правила поиска

### strict
> Режим «максимальной строгости». Если его включить, TypeScript начнет замечать любые, даже самые мелкие подозрительные места в коде и заставит писать максимально чисто и безопасно, запрещая любые поблажки

### strictNullChecks
> Очень полезная галочка внутри строгого режима. Она запрещает случайно использовать переменные, в которых вместо реальных данных лежит «ничего» (`null` или `undefined`), защищая программу от падений во время работы

### esModuleInterop
> Эта штука сглаживает углы и дружит между собой разные стандарты импортов (CommonJS и ES-модули). Благодаря ей мы можем импортировать старые библиотеки так, будто они написаны по самым современным стандартам

### skipLibCheck
> Приказывает компилятору не тратить время на проверку ошибок внутри готовых встроенных библиотек в папке `node_modules`. Это сильно ускоряет сборку нашего собственного кода

### forceConsistentCasingInFileNames
> Заставляет строго следить за регистром букв в названиях файлов. Если файл называется `Task.ts`, а мы импортируем его как `task.ts` (с маленькой буквы), компилятор выдаст ошибку. Это спасает от багов при переносе кода с Windows на Mac или Linux

### outDir
> Папка, в которую компилятор будет складывать все готовые собранные JavaScript-файлы после превращения из TypeScript. Помогает держать исходный код и результат сборки раздельно

### rootDir
> Корневая папка, где лежит наш исходный код на TypeScript (обычно это папка `src`). Компилятор смотрит туда и в точности повторяет структуру её папок внутри папки `outDir`

## include
> Список папок и файлов, которые компилятор обязан брать в работу и проверять (например, вся папка `src` с нашим кодом)

## exclude
> Чёрный список для компилятора. Сюда закидывают папки, которые проверять вообще не нужно (например, огромную папку `node_modules` или тесты), чтобы не тратить ресурсы компьютера

# Задание 1.2. Включение флагов

Для каждого пункта ниже:
1. Определите, какой флаг нужно поменять в `tsconfig.json`.
2. Внесите изменение.
3. Запустите `npm run check`.
4. Запишите результат в `task1.md`.

---

### 1. Строгие проверки типов
Включите опцию, которая делает `null` и `undefined` отдельными типами,
а не «совместимыми со всем». Без неё код с `null` компилируется, с ней — нет.

**Ваш ответ:** `strictNullChecks`

---

### 2. Проверка `this`
Включите опцию, которая ругается, если внутри функции используется `this`,
но функция не является методом класса (то есть `this` не определён).

**Ваш ответ:** `noImplicitThis`

---

### 3. Неявный `any`
Включите опцию, которая ругается, если переменная получает тип `any`
автоматически (например, функция без аннотаций параметров).

**Ваш ответ:** `noImplicitAny`

---

### 4. Возврат из функции
Включите опцию, которая требует, чтобы **все** ветки функции возвращали значение,
если функция объявлена как возвращающая не-`void`.

**Ваш ответ:** `noImplicitReturns`
